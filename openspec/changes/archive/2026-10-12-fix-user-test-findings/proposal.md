# Proposal

## Why

让一个没有上下文的 Agent 以新用户身份试用后，发现了一批作者自己测不到的问题，经逐条复现全部属实：窗口显示的步骤序号与命令行编号不一致会导致标错步骤，数据文件内部被改坏时命令行为混乱且仍会写入，名称没有长度和换行限制，对话记录读不懂时没有任何说明，写入失败会留下临时文件，以及若干不准确的报错和界面小问题。

## What Changes

- 窗口显示真实的任务编号和步骤编号，与命令行一致；修改进度的命令输出里带上步骤或任务的名称。
- 读取数据文件时校验每个任务、步骤和建议的字段，不合格与语法损坏同样处理：拒绝写入并给出路径和原因。带 BOM 的文件可以正常读取。
- 任务、步骤、建议的名称限制为单行、最多 200 个字符，命令行和窗口使用同一规则。
- `task digest` 把内容无法识别的记录和记录中读不懂的行都计入"跳过"并在末尾说明。
- 写入失败时删除本次产生的临时文件。
- 报错信息显示用户的原始输入；负数、过大的编号、不存在的时间、只有空白的身份变量都给出准确说明。
- 互相矛盾或重复给出的选项被拒绝。
- `task list` 标出每个任务的紧急程度，`--json` 输出带上状态字段。
- 窗口：名称只有空格时给出提示；刚完成的任务移动位置后保持可见。
- Agent 模板补充：任务没有步骤时怎么记进度、署名在哪些命令上生效、怎么判断哪个任务最急、怎么改截止日期。
- README 说明 Electron 在首次启动时下载，并更正 Node 的最低版本。
- 不包含：给已有进度的任务加第一个步骤时的进度处理，以及 `task done <任务>` 对有步骤任务的行为。这两项等用户确认规则后另行处理。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `task-store`: 新增数据文件完整校验、名称规则和写入失败清理三项要求。
- `task-cli`: 新增输出带名称、列表标出紧急程度、报错显示原始输入、拒绝矛盾选项四项要求。
- `desktop-widget`: 新增显示真实编号、空白名称提示、完成后保持可见三项要求。
- `conversation-digest`: 修改"读不了时不中断"，把内容无法识别的情况纳入说明。
- `agent-integration`: 新增接入说明须覆盖的几种常见请求。

## Impact

- `src/core/`：新增数据校验模块；名称规则；存储的失败清理；对话读取器的识别判断。
- `src/cli/run.js`：参数处理和输出文字。
- `src/widget/renderer/`：编号显示和几处交互。
- `integrations/` 两个模板、README、`package.json` 的 Node 版本要求。
- 行为变化：此前被接受的超长或多行名称现在会被拒绝；已存在的超长名称仍可读取，不会被判为损坏。
