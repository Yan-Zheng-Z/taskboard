# Spec Delta

## ADDED Requirements

### Requirement: 紧凑模式
小窗口 SHALL 提供收起和展开的切换。收起时窗口缩为一条窄栏，显示最近到期的未完成任务的名称、总进度和截止情况，并提示还有多少待处理的建议；展开时恢复收起前的大小。收起状态 MUST 在重新启动后保留，窄栏 MUST 仍可拖动、可隐藏。

#### Scenario: 收起
- **WHEN** 用户点击收起
- **THEN** 窗口变成一条窄栏，显示最近到期的未完成任务及其进度和截止情况

#### Scenario: 展开恢复原大小
- **WHEN** 用户把窗口调整到某个大小后收起再展开
- **THEN** 窗口回到收起前的大小

#### Scenario: 重启后保持收起
- **WHEN** 用户收起窗口后退出并重新启动
- **THEN** 窗口以窄栏的形式出现

#### Scenario: 没有未完成的任务
- **WHEN** 收起时没有任何未完成的任务
- **THEN** 窄栏说明当前没有待办任务

#### Scenario: 收起时数据变化
- **WHEN** 窗口处于收起状态时 Agent 更新了正在显示的任务的进度
- **THEN** 两秒内窄栏上的进度随之更新

### Requirement: 撤销
删除任务、删除步骤、忽略建议或采纳建议之后，小窗口 SHALL 在数秒内提供"撤销"，撤销后恢复到该操作之前的状态：被删除的任务或步骤回到原来的位置并保留原有进度，被忽略的建议重新出现且不再被记为已忽略，被采纳的建议回到建议区且由它创建的任务被移除。撤销 MUST 只还原这一次操作，不得覆盖期间其他来源所做的修改。

#### Scenario: 撤销删除任务
- **WHEN** 用户删除一个带有进度的任务后点击撤销
- **THEN** 该任务连同步骤和进度回到列表中原来的位置

#### Scenario: 撤销忽略建议
- **WHEN** 用户忽略一条建议后点击撤销
- **THEN** 该建议重新出现在建议区，之后同名建议仍可被提出

#### Scenario: 撤销采纳
- **WHEN** 用户采纳一条建议后点击撤销
- **THEN** 该建议回到建议区，由它创建的任务从列表中消失

#### Scenario: 撤销不覆盖其他修改
- **WHEN** 用户删除任务甲之后、点击撤销之前，Agent 更新了任务乙的进度
- **THEN** 撤销后任务甲恢复，任务乙保留 Agent 更新后的进度

#### Scenario: 撤销机会过期
- **WHEN** 用户在删除之后又做了另一个修改操作
- **THEN** 之前那次删除不能再被撤销
