# Proposal

## Why

步骤的百分比进度带来了几个问题：没有步骤的任务可以直接记进度，加上第一个步骤后这个进度会悄悄消失；Agent 要估算"这一步做了百分之几"，容易不准；窗口里每个步骤一条滑块，界面偏重。用户使用任务流的目的是一步一步确认任务是否完成，步骤只需要"完成"和"未完成"两种状态。另外，完成的任务目前只是排在列表末尾，越积越多，也没有回看的地方。

## What Changes

- **BREAKING** 步骤只有完成和未完成两种状态，不再有百分比。任务的总进度仍是百分比，由已完成步骤数除以步骤总数得出。
- **BREAKING** 每个任务至少有一个步骤：创建任务时必须给出步骤，任务的最后一个步骤不能删除。不再有"没有步骤、直接记进度"的任务。
- **BREAKING** 命令行取消 `task progress`；`task done <任务> <步骤>` 标记完成，新增 `task reopen <任务> <步骤>` 改回未完成；`task add` 需要至少一个 `--step`。
- 新增归档：任务的所有步骤完成时自动归档并记录完成时间。归档的任务不再出现在主列表里。归档不能手动触发，删除仍然只用于取消或建错的任务。
- 小窗口新增归档页，显示最近 7 天完成的任务，可以展开查看步骤。超过 7 天的归档任务不再显示，但数据保留，可用命令行查看。
- 归档的任务被取消勾选某一步或被添加新步骤时，自动回到主列表。
- 现有数据自动迁移：进度为 100% 的步骤算完成，其余算未完成；没有步骤的任务得到一个与任务同名的步骤。迁移前的文件保留一份备份。
- 不包含：归档任务的搜索和筛选、自定义保留天数、把归档导出。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `task-store`: 步骤与进度模型改为二元，任务必须有步骤，新增归档和旧数据迁移。
- `task-cli`: 命令随模型调整，新增查看归档。
- `desktop-widget`: 步骤改为勾选，主列表只显示未完成任务，新增归档页，撤销覆盖"刚归档"的情况。
- `task-suggestions`: 建议必须带步骤。
- `agent-integration`: 接入说明随命令调整。

## Impact

- 数据文件格式升到版本 2。旧版本的 taskboard 读不了新文件；新版本首次写入时把旧文件备份为 `tasks.v1.backup.json`。
- `src/core/`、`src/cli/`、`src/widget/` 以及全部相关测试。
- 两个 Agent 模板、README、接入文档。
- 依赖命令行的脚本如果用了 `task progress` 需要改用 `task done` / `task reopen`。
