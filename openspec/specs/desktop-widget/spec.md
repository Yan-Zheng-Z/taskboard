# desktop-widget Specification

## Purpose
在桌面上常驻显示任务、截止日期和进度，让用户不打开终端就能随时查看并手动修改进度，并且在 Agent 更新数据后立即反映出来。

## Requirements

### Requirement: 常驻桌面显示
小窗口 SHALL 无边框、保持在其他窗口之上、可拖动，并在重新启动后恢复上次的位置和大小。它 MUST 不出现在任务栏中，而是通过系统托盘图标来显示、隐藏和退出。

#### Scenario: 被其他窗口覆盖
- **WHEN** 用户切换到另一个最大化的应用
- **THEN** 小窗口仍然可见

#### Scenario: 记住位置
- **WHEN** 用户把窗口拖到屏幕右上角后退出并重新启动
- **THEN** 窗口出现在屏幕右上角

#### Scenario: 隐藏与恢复
- **WHEN** 用户点击托盘图标
- **THEN** 窗口在显示和隐藏之间切换

### Requirement: 任务概览
小窗口的主列表 SHALL 只列出未完成的任务，每个任务显示编号、名称、截止日期、剩余时间和总进度条。任务 MUST 按截止日期由近到远排列，没有截止日期的排在其后。已归档的任务 MUST NOT 出现在主列表中。

#### Scenario: 排序
- **WHEN** 存在截止日期分别为明天和下周的两个未完成任务
- **THEN** 明天截止的任务排在上面

#### Scenario: 没有任务
- **WHEN** 没有任何未完成的任务
- **THEN** 窗口显示空状态提示和添加任务的入口

#### Scenario: 完成的任务离开主列表
- **WHEN** 一个任务的所有步骤都已完成
- **THEN** 它不在主列表中

### Requirement: 截止日期紧迫程度
小窗口 SHALL 用不同的视觉状态区分未完成任务的紧迫程度：已过期、三天内到期、其他。紧迫程度 MUST 同时用文字表达，不能只靠颜色。

#### Scenario: 已过期
- **WHEN** 未完成任务的截止日期早于今天
- **THEN** 该任务以过期样式显示，并写明已过期多少天

#### Scenario: 已完成的任务不告警
- **WHEN** 任务总进度为 100 且截止日期已过
- **THEN** 该任务以完成样式显示，不显示过期告警

### Requirement: 查看与修改步骤
点击任务 SHALL 展开它的步骤列表，同一时间只展开一个任务。每个步骤显示编号、名称、是否完成、最后更新人和更新时间。用户 MUST 能用一个勾选控件把步骤标为完成或改回未完成，修改以 "user" 署名保存。

#### Scenario: 展开任务
- **WHEN** 用户点击一个任务
- **THEN** 该任务下方显示全部步骤及各自是否完成和最后更新人，之前展开的任务收起

#### Scenario: 手动改进度
- **WHEN** 用户勾选某个未完成的步骤
- **THEN** 该步骤保存为已完成，最后更新人为 "user"，任务总进度随之更新

### Requirement: 在窗口内编辑任务
小窗口 SHALL 允许用户添加任务（名称、第一个步骤和可选截止日期）、添加步骤、重命名以及删除任务和步骤。删除 MUST 先经用户确认。任务只剩一个步骤时 MUST 不提供删除该步骤的操作。

#### Scenario: 添加任务
- **WHEN** 用户在窗口中输入名称、第一个步骤和截止日期并确认
- **THEN** 新任务出现在列表中，带有这个步骤，并可用 `task list` 查到

#### Scenario: 删除需确认
- **WHEN** 用户点击删除任务
- **THEN** 窗口先请求确认，确认后才删除

#### Scenario: 只剩一个步骤
- **WHEN** 展开的任务只有一个步骤
- **THEN** 这个步骤没有删除按钮

### Requirement: 自动刷新
当数据被命令行或 Agent 修改时，小窗口 SHALL 在两秒内显示最新内容，无需用户操作，且 MUST 保持用户当前展开的任务不被折叠。

#### Scenario: Agent 更新进度
- **WHEN** 窗口打开时另一个进程运行 `task done 1 2 --by claude`
- **THEN** 两秒内窗口中该步骤显示为 100，最后更新人显示为 "claude"

### Requirement: 数据异常提示
当数据文件无法读取或解析时，小窗口 MUST 显示明确的错误状态和文件路径，并禁用所有修改操作，不得显示为空列表。

#### Scenario: 数据文件损坏
- **WHEN** 数据文件内容不合法
- **THEN** 窗口显示错误说明和文件路径，不能添加或修改任务

### Requirement: 键盘可用
小窗口中的所有操作 SHALL 可以只用键盘完成，当前焦点位置 MUST 可见。

#### Scenario: 键盘操作进度
- **WHEN** 用户用 Tab 键移动到某个步骤的勾选控件并按空格
- **THEN** 该步骤的完成状态切换并保存

### Requirement: 开机自启
小窗口 SHALL 提供一个可开关的"开机自动启动"选项，默认关闭。

#### Scenario: 开启自启
- **WHEN** 用户在托盘菜单中开启开机自启后重新登录系统
- **THEN** 小窗口自动出现

### Requirement: 建议区
存在待处理的建议时，小窗口 SHALL 在任务列表上方显示建议区，每条建议显示名称、截止日期、步骤及其中哪些已完成、来源说明和提出者，并提供"采纳"和"忽略"。没有建议时 MUST 不显示建议区。

#### Scenario: 采纳一条建议
- **WHEN** 用户点击某条建议的"采纳"
- **THEN** 该建议从建议区消失，任务列表里出现对应的任务及其步骤

#### Scenario: 忽略一条建议
- **WHEN** 用户点击某条建议的"忽略"
- **THEN** 该建议从建议区消失，任务列表不变

#### Scenario: Agent 提出建议后自动出现
- **WHEN** 窗口打开时另一个进程运行 `task suggest`
- **THEN** 两秒内建议区出现这条建议，无需用户操作

#### Scenario: 没有建议
- **WHEN** 没有待处理的建议
- **THEN** 窗口里没有建议区

### Requirement: 第一次启动的整理卡片
当从未显示过整理卡片、且没有任何任务和建议时，小窗口 SHALL 显示一张卡片，说明可以从最近的 Agent 对话里整理出任务建议，以及这会把对话摘要发给模型并消耗额度，并提供"开始整理"和"以后再说"。无论用户选择哪个，这张卡片 MUST 不再自动出现。

#### Scenario: 第一次启动
- **WHEN** 用户第一次启动小窗口，没有任何任务
- **THEN** 窗口显示整理卡片

#### Scenario: 选择以后再说
- **WHEN** 用户点击"以后再说"后重新启动小窗口
- **THEN** 卡片不再出现，窗口显示普通的空状态

#### Scenario: 已有任务的用户
- **WHEN** 已经有任务的用户升级后启动小窗口
- **THEN** 不显示整理卡片

### Requirement: 后台整理
用户点击"开始整理"后，小窗口 SHALL 在后台启动本机的 Claude Code 完成一次整理，期间显示正在进行的状态且窗口保持可用；完成后显示结果是新增了多少条建议，失败时显示原因。未安装 Claude Code 时，卡片 MUST 改为告诉用户可以对自己的 Agent 说哪句话来整理。

#### Scenario: 整理成功
- **WHEN** 后台整理完成并提出了三条建议
- **THEN** 建议区出现这三条建议，窗口说明新增了三条建议

#### Scenario: 没有可整理的内容
- **WHEN** 后台整理完成但没有提出任何建议
- **THEN** 窗口说明没有从最近的对话里找到待办事项

#### Scenario: 未安装 Claude Code
- **WHEN** 本机找不到 Claude Code
- **THEN** 卡片不提供"开始整理"，而是显示可以对 Agent 说的那句话

#### Scenario: 整理失败
- **WHEN** 后台进程出错或超过时间上限
- **THEN** 窗口显示失败原因，任务和建议数据不受影响

### Requirement: 随时手动整理
小窗口 SHALL 在标题栏提供一个"整理"按钮。点击后显示整理卡片（与第一次启动时相同的说明和隐私、额度提示），用户确认后开始后台整理；取消则关闭卡片。无论是否有任务、是否用过首次整理，这个按钮 MUST 都可用；整理进行中时 MUST 不能再次触发。

#### Scenario: 已有任务时手动整理
- **WHEN** 列表里已有任务的用户点击"整理"按钮并确认
- **THEN** 后台整理开始，完成后新的建议出现在建议区

#### Scenario: 取消
- **WHEN** 用户点击"整理"按钮后选择取消
- **THEN** 卡片关闭，没有启动任何后台进程

#### Scenario: 整理进行中
- **WHEN** 后台整理正在进行
- **THEN** "整理"按钮不可用

### Requirement: 整理结果说明
后台整理完成后，小窗口 SHALL 说明这次整理更新了哪些已有任务（任务名称，以及有多少个步骤有进展、新增了多少个步骤）和新增了多少条建议；两者都没有时说明没有需要更新或新增的内容。

#### Scenario: 更新了已有任务
- **WHEN** 后台整理把一个已有任务的一个步骤标为完成并给它加了一个步骤，同时提出了一条新建议
- **THEN** 窗口说明更新了一个已有任务并列出它的名称、一个步骤有进展、新增一个步骤，以及新增了一条建议

#### Scenario: 没有变化
- **WHEN** 后台整理既没有更新任务也没有提出建议
- **THEN** 窗口说明最近的对话里没有需要更新或新增的内容

### Requirement: 紧凑模式
小窗口 SHALL 提供收起和展开的切换。收起时窗口缩为一条窄栏，显示最近到期的未完成任务的名称、总进度和截止情况，并提示还有多少待处理的建议；展开时恢复收起前的大小。收起状态 MUST 在重新启动后保留，窄栏 MUST 仍可拖动、可隐藏。

#### Scenario: 收起
- **WHEN** 用户点击收起
- **THEN** 窗口变成一条窄栏，显示最近到期的未完成任务及其进度和截止情况

#### Scenario: 展开恢复原大小
- **WHEN** 用户把窗口调整到某个大小后收起再展开
- **THEN** 窗口回到收起前的大小

#### Scenario: 重启后保持收起
- **WHEN** 用户收起窗口后退出并重新启动
- **THEN** 窗口以窄栏的形式出现

#### Scenario: 没有未完成的任务
- **WHEN** 收起时没有任何未完成的任务
- **THEN** 窄栏说明当前没有待办任务

#### Scenario: 收起时数据变化
- **WHEN** 窗口处于收起状态时 Agent 更新了正在显示的任务的进度
- **THEN** 两秒内窄栏上的进度随之更新

### Requirement: 撤销
删除任务、删除步骤、忽略建议、采纳建议，或勾选最后一个步骤使任务归档之后，小窗口 SHALL 在数秒内提供"撤销"，撤销后恢复到该操作之前的状态：被删除的任务或步骤回到原来的位置并保留原有状态，被忽略的建议重新出现且不再被记为已忽略，被采纳的建议回到建议区且由它创建的任务被移除，刚归档的任务回到主列表且那个步骤恢复为未完成。撤销 MUST 只还原这一次操作，不得覆盖期间其他来源所做的修改。

#### Scenario: 撤销删除任务
- **WHEN** 用户删除一个已有步骤完成的任务后点击撤销
- **THEN** 该任务连同步骤和完成状态回到列表中原来的位置

#### Scenario: 撤销忽略建议
- **WHEN** 用户忽略一条建议后点击撤销
- **THEN** 该建议重新出现在建议区，之后同名建议仍可被提出

#### Scenario: 撤销采纳
- **WHEN** 用户采纳一条建议后点击撤销
- **THEN** 该建议回到建议区，由它创建的任务从列表中消失

#### Scenario: 撤销归档
- **WHEN** 用户勾选任务的最后一个未完成步骤使它归档，然后点击撤销
- **THEN** 该任务回到主列表，那个步骤恢复为未完成

#### Scenario: 撤销不覆盖其他修改
- **WHEN** 用户删除任务甲之后、点击撤销之前，Agent 完成了任务乙的一个步骤
- **THEN** 撤销后任务甲恢复，任务乙的那个步骤仍是已完成

#### Scenario: 撤销机会过期
- **WHEN** 用户在删除之后又做了另一个修改操作
- **THEN** 之前那次删除不能再被撤销

### Requirement: 显示真实编号
小窗口 SHALL 显示每个任务的编号和每个步骤的编号，且 MUST 与命令行使用的编号相同，不得用列表中的位置代替。收起后的窄栏同样显示任务编号。

#### Scenario: 删除过步骤的任务
- **WHEN** 某任务的步骤编号是 1、3、4（编号 2 已被删除）
- **THEN** 窗口里这三个步骤显示的编号是 1、3、4

#### Scenario: 任务编号
- **WHEN** 列表按截止日期排序后，编号为 5 的任务排在第一位
- **THEN** 它显示的任务编号是 5

### Requirement: 空白名称提示
在窗口里提交只含空格的任务名称或步骤名称时，小窗口 MUST 不提交并提示名称不能为空。

#### Scenario: 只输入空格
- **WHEN** 用户在添加任务的名称框里只输入空格并提交
- **THEN** 表单没有提交，窗口提示名称不能只有空格

### Requirement: 归档页
小窗口 SHALL 提供一个归档页，可从标题栏切换进入和返回。归档页列出最近若干天内完成的任务，天数由设置决定（7、14 或 30，默认 7），按完成时间由近到远排列，每个任务显示编号、名称和完成日期，可以展开查看步骤。完成时间超过该天数的任务 MUST NOT 显示。在归档页把某个步骤改回未完成或添加新步骤时，该任务 SHALL 回到主列表。

#### Scenario: 刚完成的任务
- **WHEN** 用户完成一个任务的最后一步后打开归档页
- **THEN** 该任务出现在归档页最上方，并显示今天的完成日期

#### Scenario: 超过一周
- **WHEN** 归档显示天数为 7，某个任务是 8 天前完成的
- **THEN** 它不在归档页中，但仍在数据文件里

#### Scenario: 调整显示天数
- **WHEN** 用户把归档显示天数改为 30
- **THEN** 8 天前完成的任务出现在归档页中

#### Scenario: 归档为空
- **WHEN** 设定的天数内没有完成任何任务
- **THEN** 归档页说明这段时间没有完成的任务

#### Scenario: 重新打开
- **WHEN** 用户在归档页取消勾选某个任务的一个步骤
- **THEN** 该任务从归档页消失并回到主列表

#### Scenario: Agent 完成任务后自动出现
- **WHEN** 归档页打开时另一个进程完成了某个任务的最后一步
- **THEN** 两秒内该任务出现在归档页

### Requirement: 设置页
小窗口 SHALL 提供一个设置页，可从标题栏进入和返回。设置页包含：主题（跟随系统、浅色、深色）、始终置顶、开机自动启动、归档显示天数（7、14、30）、整理时读取的对话来源和天数、数据文件位置（可打开所在文件夹）以及版本号和项目地址。每项修改 MUST 立即生效并保存，重新启动后保持；不合法的取值 MUST 被拒绝且原设置不变。

#### Scenario: 切换主题
- **WHEN** 用户在设置页把主题从跟随系统改为深色
- **THEN** 窗口立即变为深色，重新启动后仍是深色

#### Scenario: 关闭始终置顶
- **WHEN** 用户关闭始终置顶
- **THEN** 其他窗口可以盖在小窗口上面

#### Scenario: 开机自动启动
- **WHEN** 用户在设置页打开开机自动启动
- **THEN** 系统的登录项里出现 taskboard，托盘菜单里的同一开关也显示为已打开

#### Scenario: 默认值
- **WHEN** 用户第一次打开设置页
- **THEN** 主题为跟随系统，始终置顶为开，归档显示 7 天，整理读取两个 Agent 最近 7 天的对话

#### Scenario: 数据位置
- **WHEN** 用户点击打开所在文件夹
- **THEN** 系统的文件管理器打开数据文件所在的文件夹

### Requirement: Agent 接入状态
设置页 SHALL 列出 Claude Code 和 DeepSeek Harness，对每一个显示是否在本机检测到，以及 taskboard 的接入说明是未安装、已安装还是需要更新，并提供安装或更新的按钮。只有用户点击该按钮时，小窗口才 MUST 把接入说明写入对应 Agent 的目录；写入失败 MUST 显示原因。

#### Scenario: 尚未安装
- **WHEN** 本机有 Claude Code 但还没有安装 taskboard 的接入说明
- **THEN** 设置页显示 Claude Code 已检测到、接入说明未安装，并有安装按钮

#### Scenario: 一键安装
- **WHEN** 用户点击安装
- **THEN** 接入说明被复制到该 Agent 的目录，状态变为已安装

#### Scenario: 需要更新
- **WHEN** 已安装的接入说明与当前版本的内容不同
- **THEN** 状态显示为需要更新，按钮为更新；点击后变为已安装

#### Scenario: 没有检测到
- **WHEN** 本机没有 DeepSeek Harness
- **THEN** 设置页显示未检测到，仍可安装以备之后使用
