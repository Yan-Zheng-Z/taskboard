# 前端快速体检

按 `review-frontend-production` 的快速体检流程做的**部分审查**，不代表完整覆盖或发布就绪。

## 范围与基线

- 对象：`src/widget/renderer/`（一个窗口，三个文件）以及它依赖的预加载接口。
- 日期：2026-10-12。环境：Windows 11，Electron 44.7.0，窗口 340×520。
- 检查的三条路径：添加任务；展开任务查看步骤；修改步骤进度。连带检查了删除确认、外部更新后的自动刷新和数据损坏状态。
- 证据类型：阅读源码，加上用脚本驱动真实窗口（`scripts/capture.js` 在页面里执行操作并读回结果）、真实键盘事件和截图。每个修复都先在修复前的代码上确认检查失败，再在修复后确认通过。

## 发现与处理

| # | 级别 | 问题 | 影响 | 处理 | 复验 |
|---|---|---|---|---|---|
| 1 | P2 | 拖动滑块被系统取消（`pointercancel`，触屏和触控笔常见）后，"正在拖动"的标记不会复位 | 之后 Agent 的更新不再显示，窗口停在旧数据上，直到重启 | 已修：`pointercancel` 和窗口失焦都结束拖动状态 | 脚本：取消拖动后新增步骤，1.2 秒内列表多出一项。修复前失败，修复后通过 |
| 2 | P2 | "还剩 N 天"只在数据变化时重新计算 | 窗口整夜开着且数据没变时，过了零点仍显示昨天的天数，过期任务不变红 | 已修：主进程每分钟推送一次状态 | 读源码确认；没有做跨零点的实测 |
| 3 | P2 | 删除确认出现时焦点落在"删除"按钮上 | 键盘用户连按两次回车就会删掉任务或步骤 | 已修：焦点落在"取消" | 脚本：点删除后当前焦点是"取消"。修复前失败，修复后通过 |
| 4 | P2 | 没选日期也能填时间，提交时时间被悄悄丢弃 | 用户以为设了截止时间，实际没有 | 已修：没选日期时时间框不可用 | 脚本：未选日期时禁用，选日期后可用。修复前失败，修复后通过 |
| 5 | P3 | 滑块步长是 5，Agent 设的 53% 会被显示在 55 的位置 | 滑块位置和旁边的数字不一致 | 已修：步长改为 1 | 脚本：值为 53 的步骤滑块读回 53。修复前失败，修复后通过 |
| 6 | P3 | 拖动时 `aria-valuetext` 不更新 | 读屏软件在拖动过程中读到旧值 | 已修：随输入更新 | 脚本：输入 40 后属性为 `40%`。修复前失败，修复后通过 |
| 7 | P3 | 删除步骤后焦点丢失 | 键盘用户要从头按 Tab 找回位置 | 已修：焦点回到该任务的标题；删除任务后回到"添加任务"按钮 | 脚本：删除后当前焦点是任务标题。修复前失败，修复后通过 |
| 8 | P3 | 操作失败时的原因是英文（来自与命令行共用的核心逻辑），界面其余部分是中文 | 提示语言不一致；正常使用中表单已拦住大部分错误输入，很少出现 | 未修：第一版不做界面多语言，统一错误文案留到那时一起做 | — |

## 检查过、没有发现问题的地方

- 用户输入的文字全部用 `textContent` 写入，页面没有任何把文本当 HTML 解析的地方；内容安全策略禁止内联脚本和远程资源。
- 页面里拿不到 `require` 和 `process`，只能调用预加载脚本暴露的四个方法；主进程只接受白名单内的操作名。
- 外部更新到达时，已展开的任务保持展开，输入到一半的文字和焦点都保留。
- 只用键盘可以完成"移动到任务 → 展开 → 移到滑块 → 调整进度"，保存后署名为 `user`，焦点轮廓可见。
- 数据文件损坏时显示错误和文件路径，添加按钮禁用，不显示为空列表，原文件未被改动。
- 浅色和深色两种配色都截图看过。

## 没有检查的范围

- 托盘图标的点击和右键菜单、用鼠标拖动窗口、盖在全屏应用之上的置顶效果：脚本驱动不了系统托盘和窗口拖动，需要人工操作确认。
- 开机自启：确认了开关能正确写入和清除系统登录项，没有做"重新登录后窗口自动出现"的实测。
- 多显示器、高缩放比例（125%、150%）、触屏。
- 读屏软件的实际朗读效果。
- 几十个任务以上时的滚动和性能。
- macOS 和 Linux。

## 下一步

以上未检查项里，托盘、拖动和置顶需要在日常使用中确认；其余在有人反馈问题或要正式发布安装包时再做完整审查。

# 第二次快速体检：建议区与整理卡片

同样是**部分审查**。日期 2026-10-12，环境同上。

## 范围

- 对象：`renderer.js` 里新增的建议区和"从最近的对话里整理任务"卡片。
- 路径：第一次启动看到卡片 → 开始整理 → 建议出现 → 采纳或忽略；以及"以后再说"、未安装 Claude Code、整理失败、整理进行中。
- 证据：脚本驱动真实窗口，后台整理用替身程序代替 Claude Code（成功、无结果、失败、不结束四种）；另用真实的 Claude Code 在一个临时数据目录里完整跑过一次（20 秒，提出 3 条带来源的建议，没有创建正式任务）。

## 发现与处理

| # | 级别 | 问题 | 影响 | 处理 | 复验 |
|---|---|---|---|---|---|
| 1 | P2 | 退出小窗口时，正在进行的后台整理进程不会被终止 | 最长 5 分钟内留着一个在后台消耗额度的 Agent 进程 | 已修：停止窗口时终止该进程 | 自动测试：取消后 5 秒内结束且不再处于进行中 |
| 2 | P3 | 快速连点"采纳"两次，第二次报"建议不存在"的错误 | 出现一条无意义的失败提示 | 已修：保存期间忽略重复点击 | 脚本：连点两次后没有错误提示，只生成一个任务。修复前失败，修复后通过 |
| 3 | P3 | 整理开始和结束对读屏软件没有提示（卡片每次刷新都被重建，不能当作播报区域） | 读屏用户不知道后台整理何时完成 | 已修：增加一个常驻的状态播报区域，只在阶段变化时更新 | 脚本：整理完成后播报区域的文字包含新增条数。修复前失败，修复后通过 |
| 4 | P3 | 点"开始整理"后按钮所在的卡片被替换，键盘焦点丢失 | 键盘用户要重新按 Tab | 未修：把焦点强行移到别处同样打断操作；阶段变化已有播报 | — |

## 检查过、没有发现问题的地方

- 采纳后任务出现在列表、建议消失；忽略后建议消失、任务不变；处理完一条后焦点移到下一条，全部处理完后回到"添加任务"。
- 窗口打开时由命令行提出的建议在几秒内出现在建议区。
- 没有建议时不显示建议区；已有任务的用户不会看到整理卡片；选"以后再说"后重启不再出现。
- 未安装 Claude Code 时不提供"开始整理"，改为说明可以对 Agent 说哪句话。
- 整理失败时显示原因，任务和建议数据不变。
- 建议的名称、来源等文字全部按纯文本写入。
- 传给 Claude Code 的提示词是固定文本，不含任何任务数据或对话内容，只放行 `task` 命令。

## 没有检查的范围

- 真实的 Claude Code 后台整理只跑过一次；归纳质量因对话内容而异，没有系统评估。
- DeepSeek Harness 里手动说"整理一下任务"的效果，需要在它的界面里确认。
- 浅色配色下的新界面、读屏软件的实际朗读、建议很多（几十条）时的显示。

# 第三次快速体检：撤销、紧凑模式和新版式

同样是**部分审查**。日期 2026-10-12，环境同上。

## 范围

- 对象：撤销提示条、收起后的窄栏、重新设计的配色和版式。
- 证据：脚本驱动真实窗口并读回结果；浅色和深色下的任务列表、展开的任务、建议区、撤销提示条、窄栏截图。

## 检查结果

- 撤销：删除步骤、删除任务、忽略建议、采纳建议四种操作，撤销后都回到操作前的状态（步骤回到原位置并保留 60% 的进度，任务回到原来的排序位置，建议回到建议区）。
- 紧凑模式：收起后窗口为 340×44，显示最近到期的未完成任务、进度、剩余时间和建议数量；窗口打开时由命令行更新进度，窄栏随之从 0% 变为 50%；退出后重新启动仍是窄栏；展开后回到 340×520。
- 版式：主要文字和次要文字与背景的对比度都在 4.5:1 以上（浅色下次要文字约 5:1，深色下约 7:1）；紧迫程度仍然同时用文字表达；焦点轮廓可见。
- 整理卡片、空状态和错误状态在新配色下也各截图看过。
- 标题栏图标原先用的是文字符号，在浅色下被系统字体渲染成了蓝色且大小不一，已改为线条图标。

## 发现

| # | 级别 | 问题 | 处理 |
|---|---|---|---|
| 1 | P3 | 撤销提示条固定在窗口底部，显示的 8 秒内会盖住列表最后一项 | 未修：时间短，且列表可以滚动 |
| 2 | P3 | 收起状态下看不到整理卡片，后台整理的开始和结束只有读屏播报，窄栏上只在完成后出现"建议 N" | 未修：整理只能在展开状态下发起，结果会以建议数量体现 |

## 没有检查的范围

- 用鼠标拖动窄栏、在窄栏状态下调整宽度的手感，以及 125% 和 150% 缩放下窄栏的高度是否合适。
- 窄栏底部 2 像素的进度线在截图里看不清，没有单独确认。

## 代码审查后补充

代码审查另外指出三处，均已修复并复验：撤销失败后提示条不消失（脚本：让撤销无处可还原，点击后提示条消失并显示原因）；调整窗口大小后立刻收起会丢失新尺寸、移动窄栏后立刻展开会跳回旧位置（脚本：连续操作后高度和位置都保留）；已忽略名单满员时撤销忽略不能完全还原名单（自动测试）。三项都先确认了修复前失败。

# 第四次快速体检：勾选步骤与归档页

同样是**部分审查**。日期 2026-10-12，环境同上。

## 范围

- 对象：步骤从滑块改为勾选框之后的任务卡片、添加任务表单里的"第一个步骤"、归档页、"已完成并归档"的撤销。
- 证据：脚本驱动真实窗口并读回结果；浅色下展开的任务、深色下的归档页截图。

## 检查结果

- 勾选和取消勾选步骤后，任务进度随之变化（3 步里从 1 步到 2 步，33% 变 67%），窗口里不再有滑块。
- 添加任务：不填第一个步骤时表单不提交；填了之后任务出现在列表里并带有这个步骤。
- 只有一个步骤的任务，这个步骤没有删除按钮。
- 勾完最后一步：任务离开主列表，底部出现"已完成并归档「任务名」"和撤销；撤销后任务回到列表，那一步恢复为未完成，署名也恢复原样。
- 归档页：按完成时间由近到远列出，显示"月-日 完成"；在归档页取消勾选一步后，任务从归档页消失并回到主列表。
- 归档页打开时切回任务页、再点"整理"或"＋"，都会回到任务页。

## 发现

| # | 级别 | 问题 | 处理 |
|---|---|---|---|
| 1 | P3 | 勾完最后一步后任务立刻从眼前消失，焦点随之丢失 | 未修：底部的撤销提示条说明了发生了什么并可以恢复；键盘用户按 Tab 可到达撤销按钮 |
| 2 | P3 | 归档页里的任务仍可添加步骤和改名，和主列表完全一样，没有明显提示"这样做会让它回到任务列表" | 未修：页面底部有一行说明；行为本身符合规格 |

## 没有检查的范围

- 用真实鼠标点击勾选框的手感、在触屏上的可点区域大小。
- 归档里有几十个任务时的滚动。
- 整理卡片在新模型下的结果文字只用替身程序看过。
